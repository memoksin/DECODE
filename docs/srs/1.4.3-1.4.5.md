## 1.4.3 User Characteristics

Written for DEC-29 (1.4.3), DEC-50 (1.4.4), DEC-51 (1.4.5); matches the SRS report. Sources: Toplantı 2 (21 Oct), DEC-44 (MiroTalk), DEC-45 (camera), SRS 1.4.2/2.2 draft, DEC-25 draft.

- **Interviewer**

  HR staff or technical interviewer who opens an interview session for a position and invites candidates via a link. A programming background is not required, but is possible. The interviewer may be HR staff without programming experience or a technical interviewer who programmes. Eye-tracking knowledge is not expected, so the report must be readable without eye-tracking training. Decode's web client can be accessed via a desktop browser, so there is no need to install anything before logging in. This means that interviewers only need everyday web skills. Interviewers view the classification as supplementary information that reinforces their decision, not as a hiring decision.

- **Candidate**

  Candidates range from novices to experienced programmers, and DECODE estimates this level. They must be able to read Java because the code snippets and trending paths are written in this language. They will also need a laptop or desktop computer with a webcam of at least 720p at 30 fps (1080p is recommended), a modern web browser, and a stable internet connection. During calibration and reading, candidates should sit facing the camera in reasonable lighting and keep head movement to a minimum. Glasses and certain eye conditions, such as strabismus, as well as reading difficulties, such as dyslexia, may affect gaze accuracy and reading patterns. Candidates can therefore decline eye tracking at the consent stage. If they do take part, the interviewer will see a data quality warning whenever gaze quality is low.

## 1.4.4 Limitations

These items limit the design options. They do not repeat the scope limitations in 1.2.

- DECODE can only use the candidate's consumer webcam, not an infrared eye tracker. Webcam gaze models have an error of 2–4°, while one line of code covers about 0.5°, so gaze can only be mapped to code blocks.
- Face and eye images are personal data under GDPR and KVKK. The candidate must give explicit consent before recording, and the video can be kept only as long as the analysis needs it.
- Trending paths can only be built from public, labelled eye-tracking datasets, because collecting our own labelled data is out of scope. This limits the model to Java and to the code snippets used in those datasets.
- The videoconferencing platform is a fork of MiroTalk SFU, which is licensed under AGPL-3.0, so every change we make to it must be published as open source.
- The system is built by four students over two semesters (28 weeks), and the COCOMO II estimate is about 2.2 times this capacity. The core interview path is therefore built first, and the research pipeline is kept as scripts.

## 1.4.5 Assumptions and Dependencies

**Assumptions**

- Trending paths built from datasets recorded with research-grade eye trackers can be compared with webcam scanpaths once both are mapped to the same code blocks.
- The experience labels in the datasets (self-rated expertise, years of programming or the authors' groups) reflect the participants' real programming experience.
- While reading the code, the candidate looks at DECODE's code view and does not read the code from another window or from paper.

**Dependencies**

- The videoconferencing part depends on MiroTalk SFU, an open-source project with a single maintainer and no release tags, so our fork is pinned to one version.
- Gaze estimation depends on pretrained models, MediaPipe Face Landmarker and/or L2CS-Net, which are not trained by us. We will choose between them after testing both on the same recordings.
- The STA model depends on public datasets staying available (EMIP on OSF, Peitek et al. on GitHub) under licences that allow research use.
